A Diagram Modulo Can Read





Modulo reads a structured subset of ISO 5807 flowchart notation from one single-page PNG, JPG/JPEG, SVG, or PDF. Clean digital exports work best. Every chart in the Try A Sample rotation follows these rules and converts end to end, so they are good models to copy.


Shapes




Rounded rectangle or oval: Start / End


Exactly one Start. End the program with End. Begin, Stop, Exit, Finish and Halt are also accepted, in any letter case. The terminal contains only that word.


Rectangle: process


One statement per box: an assignment such as total = total + n or count = 0. Two worded operations are also supported: Calculate factorial (or Calculate factorial of n) and Declare variables a, b and c. Any other plain-language text is reported as unsupported rather than guessed.


Parallelogram: input


Input n, Input n:int (also :float or :str), Input a, b and c, or Input variable: n. An untyped input that is compared with a number becomes an integer input.


Parallelogram: output


Output total prints a variable or expression. Put literal text in quotes: Output "Even". An unquoted single word that is not a variable in the chart, such as Output Even, is printed as text and flagged for review.


Diamond: decision


A condition such as n > 0 or n % 2 == 0. A leading if, a trailing ?, and question wording such as is a > b? are accepted. Write equality as ==; a lone = is read as equality only when nothing else makes sense.


Hexagon: loop header


WHILE count <= 5 or FOR i IN range(1, 11). A diamond that an arrow loops back to is also read as a WHILE loop.




Arrows and branches


    

  • Use solid straight or right-angled lines with one clearly visible, filled arrowhead at the target end. Each arrow must start and end on a shape outline.
    • 

  • Every shape except a decision or loop header has exactly one outgoing arrow. Several arrows may join into one arrowhead before a shape.
    • 

  • A decision or loop header has exactly two outgoing arrows, labeled Yes and No (True/False and Y/N also work). Place each label beside its arrow near the diamond, not on top of the line or arrowhead.
    • 

  • For an if without an else, send the No arrow on to the next shape. Branches should rejoin before continuing or ending.
    • 

  • For a loop, Yes enters the body and No leaves the loop. The last body shape arrows back into the loop header. A post-test (do-while) loop, with the body drawn before the diamond, is also supported.
    • 

  • A loop must have a single exit: its header's No arrow. An arrow that leaves the loop body directly (for example straight to End), or a second path out of the loop, is rejected as unstructured flow.
    • 

  • Decisions inside a pre-test loop body are supported; route both branches back to a shared step before the loop returns to its header. A decision inside a post-test (do-while) loop body is not yet supported.
    • 



Layout and text


    

  • Dark lines and text on a light background. Filled colored shapes are fine if the text contrasts clearly.
    • 

  • Keep shapes separate, avoid crossing arrows, and route arrows around shapes rather than close past them.
    • 

  • Use a large, plain font and put spaces around operators (i = i + 1). Small or tightly spaced text is the most common cause of misread statements.
    • 

  • Keep the page upright and sharp. Low-resolution, blurred, or rotated scans (more than about 1.5°) frequently lose arrows or labels. Photographs and hand-drawn diagrams are accepted but are less reliable.
    • 



Accepted but not yet verified


Matching small connector circles (for example two circles labeled A) and process boxes containing only break, continue, or return are parsed, but no reference diagram tests them yet. Prefer a direct arrow and a structured loop exit.


Reading the score: Excellent (90+) and Good (80+) mean recognition is reliable. Moderate (70+) means check the flagged elements. Low or Very Low means a blocking problem or an unreliable element; fix the flagged item or the diagram before relying on the result.
